# 核心高级特性开发规划 (Core Features)

## 任务背景
目前的 `rgit` MVP 版本已经具备了完整的 Git 底层对象操作和常规生命周期链路，并采用了严格的双向兼容 Disk 引擎。但在实际开发体验上，仍然缺少以下四个核心刚需：
1. **文件删除提交**：`rgit add` 目前无法感知和处理已删除文件，缺失 `rgit rm`。
2. **`.gitignore` 支持**：无法过滤 `target/` 等编译产物，导致 `rgit status` 和 `add .` 受到严重污染。
3. **代码差异比对**：缺少 `rgit diff`，提交前无法进行代码审查。
4. **工作区储藏**：缺少 `rgit stash`，无法在脏状态下安全地切换分支。

## 架构原则 (Architecture Philosophy)
**严格遵守底层重构下沉的原则：**
所有具有通用性的核心业务逻辑（例如遍历两棵树生成差异结构、维护 Stash 栈指针、解析 Ignore 树）**必须全部实现在 `rustgit` 库的 API 中**。
`rustgit-cmd` 仓库只允许作为轻薄的命令行外壳，负责：调用库 API -> 格式化输出到终端。

## 目标交付
- 使得 `rgit` 从一个理论上可跑通的底层引擎，转变为日常真正“好用”的开发者工具箱。
