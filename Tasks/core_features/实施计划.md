# 核心高级特性实施计划 (Core Features Implementation Plan)

## 阶段 1: 文件删除与追踪增强 (Remove & Add)
**目标**: 正确识别、暂存并同步被删除的文件状态到原生 `.git/index` 中，且严格遵循“存储引擎可替换”的底层架构。
**核心修改**:
- `rustgit` (架构层面): 彻底重构 `StateStore` trait 中的 `write_index` 接口。当前接口接受 `&str` 并迫使 `DiskStorage` 反向读取物理磁盘。重构后，`write_index` 将直接接受 `Repository` 内部的 `root` Tree 数据或遍历迭代器。这样不论是 Memory、KV 还是 Disk 引擎，都能统一基于核心库中严格构建的 `self.staged` 内存树结构来无副作用地序列化自己的 Index 状态，不再受限于磁盘文件存在与否。
- `rustgit-cmd`: 修复 `add.rs`，当尝试 `add` 丢失的物理文件且该文件存在于 index 时，调用 `repo.stage(path, None)` 声明该文件已被删除；实现 `commands/rm.rs`。
**成功标准**: 可以手动 `rm a.txt`，随后运行 `rgit add a.txt`（或 `rgit rm a.txt`），执行 `rgit status` 时显示该文件为 `已删除(deleted)` 并且能在提交时生成不包含该文件的 Tree。
**状态**: 已完成

## 阶段 2: .gitignore 支持 (Ignore parsing)
**目标**: 引入对 `.gitignore` 规则的支持，对未跟踪文件和编译产物进行静默。
**核心修改**:
- `rustgit`: 在核心库中引入 `.gitignore` 解析能力（拟引入标准的轻量级匹配算法或第三方 ignore 库，需用户确认引入依赖是否可接受，若不可接受则手写极简匹配）。
- `rustgit-cmd`: 在 `status.rs` 和 `add.rs` 遍历物理目录时，自动注入 ignore 规则过滤器。
**成功标准**: 在仓库根目录建立 `.gitignore` 并写入 `target/`，运行 `rgit status` 不再显示数千个未经追踪的临时文件。
**状态**: 已完成

## 阶段 3: 代码审查能力增强 (Diff Engine)
**目标**: 实现 `rgit diff`，并在核心层下沉 Diff 计算能力。
**核心修改**:
- `rustgit`: 暴露 `diff_tree_to_tree` 和 `diff_index_to_worktree` 的核心方法。结合类似 `similar` 库的 Myers Diff 算法，产出带行列号的结构化变更数据。
- `rustgit-cmd`: 新增 `commands/diff.rs`，渲染并打印带有标准红绿字符标记的补丁数据。
**成功标准**: 能够运行 `rgit diff` 并看到具体的增删代码行，且和原生 `git diff` 输出格式大体一致。
**状态**: 已完成

## 阶段 4: 工作区储藏 (Stash Management)
**目标**: 实现安全的暂存区与工作区进栈、出栈保护机制。
**核心修改**:
- `rustgit`: 在 `Repository` 实现 `stash_save(msg)` 和 `stash_pop()` 方法，基于当前的 Index 与 Working Tree 生成 Dangling Commit（没有父节点的孤儿节点，或者伪造的二叉合并节点）并存入 `refs/stash` 栈。
- `rustgit-cmd`: 新增 `commands/stash.rs`，调用对应核心库 API。
**成功标准**: 在工作区脏乱的情况下，运行 `rgit stash` 会清空工作区与暂存区，并恢复到 HEAD 状态；随后运行 `rgit stash pop` 可以重新还原出刚才脏乱的代码状态。
**状态**: 已完成
