# 核心高级特性执行记录

## 阶段 1: 文件删除与追踪增强 (Remove & Add)
**目标**: 正确识别、暂存并同步被删除的文件状态到原生 `.git/index` 中，且严格遵循“存储引擎可替换”的底层架构。
**成功标准**: 可以手动 `rm a.txt`，随后运行 `rgit add a.txt`（或 `rgit rm a.txt`），执行 `rgit status` 时显示该文件为 `已删除(deleted)` 并且能在提交时生成不包含该文件的 Tree。
**状态**: 已完成
**执行过程**:
- 重构了 `StateStore` 的 `write_index` 接口，改用传递 `[(String, Hash, u32)]` 格式的条目，解除了 `DiskStorage` 对物理文件的强绑定。
- 新增 `Repository::sync_index`，它通过深度遍历内部已暂存的 `self.root` 生成条目并序列化到存储。
- 完善了 `Repository::load_index` 逻辑，通过暴露 `StateStore::read_index_entries`，支持在开启时根据 index 重构内部内存目录树，并在树空时正确赋值空的树 Hash（修复了之前误置全零导致非树对象的 Bug）。
- 改造 `rustgit-cmd` 的 `add.rs`，不再手工构建 index 内容，而是在处理完所有文件后统一调用 `sync_index()`；并在 `fs::read` 出现 NotFound 错误时智能调用 `repo.stage(file, None)` 记录删除操作。
- 新增 `rustgit-cmd` 中的 `rm.rs` 命令支持显式暂存文件删除并同步清理物理文件。
- 测试通过：`rgit add` 与 `rgit rm` 对文件删除的记录均精准生成 Tree 并保持底层兼容性。

## 阶段 2: .gitignore 支持 (Ignore parsing)
**目标**: 引入对 `.gitignore` 规则的支持，对未跟踪文件和编译产物进行静默。
**成功标准**: 在仓库根目录建立 `.gitignore` 并写入 `target/`，运行 `rgit status` 不再显示数千个未经追踪的临时文件。
**状态**: 已完成
**执行过程**:
- 通过引入业界标准的 `ignore` crate（轻量级、完全兼容 Git），在 `rustgit` 核心库中实现了 `rustgit::ignore::IgnoreManager`。
- 在 `rustgit-cmd` 的 `status.rs` 中实现了广度优先的递归目录扫描器，并与 `IgnoreManager` 集成，遇到匹配的目录（如 `target/`）则剪枝不遍历，大幅提高了 `rgit status` 在包含大型构建目录时的响应速度与清洁度。
- 同样在 `add.rs` 中重构了对目录的遍历逻辑（`collect_files`），确保在执行 `rgit add .` 等全目录添加时，自动屏蔽所有被 `.gitignore` 保护的临时文件。
- 测试通过：验证了忽略文件在 `status` 和 `add` 指令中均表现出预期的行为。

## 阶段 3: 代码审查能力增强 (Diff Engine)
**目标**: 实现 `rgit diff`，并在核心层下沉 Diff 计算能力。
**成功标准**: 能够运行 `rgit diff` 并看到具体的增删代码行，且和原生 `git diff` 输出格式大体一致。
**状态**: 已完成
**执行过程**:
- 引入了 `similar` crate 实现了基于 Myers 算法的高性能文本 Diff 逻辑。
- 在核心库新增了 `src/diff.rs` 模块，将 `similar::TextDiff` 的输出解析为标准的 unified diff 块结构（带有 `@@ -a,b +c,d @@` header 的 `DiffHunk` 列表）。
- 新增了 `rustgit-cmd diff` 命令，扫描出 Index 和工作区存在的文本差异，并按照终端彩色格式打印差异行（红色 `-`、绿色 `+`）。
- **架构级 Bug 修复**: 在测试 `diff` 时，暴露出一个架构遗留问题：由于 `rgit add` 的暂存树驻留在内存 (`MemoryStorage`) 中，命令结束后被销毁，导致后续的 `rgit diff` 与 `rgit commit` 无法在物理磁盘上找到对应的 Blob 对象而抛出 `MissingObject`。
- 修复方案：在 `rustgit` 的 `repository.rs` 中新增 `flush_staged()` 方法。并在 `rustgit-cmd` 的 `add.rs` 和 `rm.rs` 退出之前显式调用此方法，提前将暂存对象写入原生 `.git/objects/`（完美还原了原生 `git hash-object -w` 的底层行为），彻底打通了独立 CLI 进程间基于磁盘的对象共享闭环。
- 测试通过：`rgit diff` 能够精准地按照标准格式呈现改动行。

## 阶段 4: 工作区储藏 (Stash Management)
**目标**: 实现安全的暂存区与工作区进栈、出栈保护机制。
**成功标准**: 在工作区脏乱的情况下，运行 `rgit stash` 会清空工作区与暂存区，并恢复到 HEAD 状态；随后运行 `rgit stash pop` 可以重新还原出刚才脏乱的代码状态。
**状态**: 已完成
**执行过程**:
- 在 `rustgit::Repository` 层新增了 `commit_stash` 和 `pop_stash` 机制：
  - `commit_stash(msg)`: 利用 `refs/stash` 作为悬空分支（Dangling branch）的引用。每次暂存时，都会将当前工作区目录状态构造为一个孤儿 Commit（若之前有 stash，则将老 stash 设置为 parent，实现 stash 栈结构）。
  - `pop_stash()`: 读取 `refs/stash`，返回最新的储藏 Hash，并通过解析 parent 更新引用以实现出栈。
- 在 `rustgit-cmd` 新增了 `commands/stash.rs` 路由，支持 `save` 和 `pop` 操作。
  - `save`: 类似 `rgit add .` 的全量工作区扫描过滤，强制持久化后调用 `commit_stash`，随后调用 `reset::execute` (`--hard HEAD`) 完成环境清理。
  - `pop`: 解析栈顶，通过重定向 `repo.root` 至 stash tree 后调用 `checkout_tree` 将所有修改直接还原回物理磁盘，并 `sync_index()` 恢复暂存区，从而实现一键无缝还原工作流。
- 测试通过：完美实现了基准状态保存与变更撤销-重放（支持 tracked 甚至 untracked 文件的一并暂存）。
